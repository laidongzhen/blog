# HTTP请求

> 读完只需要能答文末 3 问。细节用的时候再翻。

## 1. 先记住这句

> 页面只管喊「给我这份数据」；加通行证、拆包装、报失败，全是快递中转站的事。

把 `src/utils/http` 想成公司唯一的快递站：

- 业务页**不要自己去邮局**（不要直接 axios）。
- 你在 `src/api/*.ts` 填运单（url、参数），调用 `request.get/post/...`。
- 中转站出门前给包裹贴工牌（Token），回来只把**箱子里的货**交给你。
- 工牌过期（401），中转站赶人回登录页，3 秒内只赶一次，避免大厅炸锅。

## 2. 什么时候会碰到

- 新写一个列表/保存接口
- 登录失败、登录过期被踢
- 上传文件或下载模板
- 接口成功了但页面拿不到 `items`
- 想关掉某个接口的错误弹窗

## 3. 一条链路看懂

以「打开角色列表」为例：

1. 页面喊：`fetchGetRolePaging(...)`
2. 运单进中转站：自动贴 `Authorization`（里面已经带 `Bearer `）
3. 普通 JSON 会帮你 `JSON.stringify`；如果是文件袋（`FormData`）就原样送，不拆袋
4. 后端回一个箱子：`{ code, message, data }`
5. `code === '200'`：把 **`data` 这一层**交给页面
6. `code === '401'` 或 HTTP 401：登出
7. 其它失败：弹 `message`，Promise reject

```text
页面 fetchXxx  →  贴工牌  →  发出去  →  看 code
                                      ├ 200：给你 data
                                      ├ 401：赶去登录
                                      └ 其它：弹错
```

## 4. 业务页怎么写

推荐：只调 `src/api` 里的函数，页面拿到的已经是货。

```6:11:src/api/role.ts
export const fetchGetRolePaging = (data: Role.IReqGetRolePaging) => {
  return request.post<Role.IResGetRolePagingData>({
    url: '/api/sys_role/paging',
    data
  })
}
```

登录还没有工牌，必须告诉中转站「这次别贴」：

```9:16:src/api/auth.ts
export function fetchLogin(data: Auth.LoginParams, config: ApiRequestConfig = {}) {
  return request.post<Auth.LoginResponse>({
    url: '/api/auth-manage/login',
    data,
    ...config,
    skipAuth: true
```

**不要这样**：`const list = (await fetchGetRolePaging(p)).data.items`  
中转站已经拆过箱，再 `.data` 会拿到 `undefined`。

| 想改什么 | 打开哪个文件 |
|----------|----------------|
| 超时、baseURL | `src/utils/http/index.ts` |
| 弹错文案、错误类型 | `src/utils/http/error.ts` |
| 某个接口不弹错 / 要成功 toast | 该接口的 `showErrorMessage` / `showSuccessMessage` |
| 登录加密 | `src/store/modules/user.ts` + `src/utils/encode/gmCrypt.ts` |

## 5. 只要记住这几个点

### 你拿到的是货，不是箱子

**类比**：快递员把泡沫箱拆了，只把衣服递到你手上。你再找「箱子」就没有了。

**代码里**：成功时只 `return res.data.data`。`code` 必须是字符串 `'200'`，不是数字 200。

```205:209:src/utils/http/index.ts
    if (config.responseType === 'blob') {
      return res.data as T
    }
    return res.data.data as T
```

文件流（blob）是例外：那一趟运的就是文件本身，不再拆 `data`。

**合上书记住**：`await fetchXxx()` 的结果 = 后端 `data`。

**别这样**：页面再取一次 `.data`，或把成功码改成数字 200。

### 工牌出门前已经戴好

**类比**：保安室进门前就把工牌打印成「Bearer + 编号」。门卫只负责别上胸口，不再写一遍「Bearer」。

**代码里**：`setToken` 拼好前缀；拦截器原样塞进头。登录用 `skipAuth` 摘掉头，免得过期工牌把登录请求也卡死。

```67:70:src/utils/http/index.ts
    if (request.skipAuth === true) {
      request.headers.delete('Authorization')
    } else if (accessToken) {
      request.headers.set('Authorization', accessToken)
```

同一枚 Token，HTTP 带着 Bearer 用；后面讲的 Socket 会把 Bearer **剥掉**再用。记住「两套门卫规矩不一样」即可。

**合上书记住**：拦截器不加第二层 Bearer。

**别这样**：在拦截器里再写 ``Bearer ${accessToken}``。

### 过期只赶人一次

**类比**：大厅同时 10 个包裹被拒，保安只广播一次「请去前台办证」，不会赶 10 趟。

**代码里**：第一次 401 才 `logOut` + 弹错，3 秒内后面的 401 只失败、不再登出。业务 `catch` 里也不要再弹「登录过期」。

**合上书记住**：401 = 回登录；连弹是中转站已经防过的。

**别这样**：每个页面 catch 401 再 toast 一次。

### 账号密码先加密再上路

**类比**：运单上的姓名密码要先盖章（SM4），中转站不管盖章，盖章发生在出发前的仓库。

**代码里**：`userStore.login` 里 `encryptFun` 后再 `fetchLogin`。登录接口本身不要再加密一遍。

**合上书记住**：加密在 store / 用户 API，不在 http 拦截器。

**别这样**：在 `src/api/auth.ts` 再 `encryptFun` 一次。

## 6. 别踩这些坑

- 文件里写了重试，但次数是 0，等于没重试。`src/utils/http/index.ts`
- 成功请求会 `console.log` 一整包响应。同文件
- `refreshToken` 存了字段，登录没真正走刷新流程。`src/store/modules/user.ts`
- 浏览器下载文件的 `downloadUrl` **不经过**这套中转站，改 Token 头帮不上它。见《文件上传与下载》

## 7. 合上书自测

1. 页面 `await fetchXxx()` 拿到的是整包 `{ code, data }` 还是里面的 `data`？
2. 为什么登录接口要写 `skipAuth: true`？
3. 同时 10 个接口 401，用户会被踢几次登录页？

# 全局通信-WebSocket

> 读完只需要能答文末 3 问。细节用的时候再翻。

## 1. 先记住这句

> 全公司只有一部总机；页面不要自己拉线，订个频道听广播就行。

名字叫 WebSocket，干活的其实是 **SignalR 总机**：

- 登录成功后，`App.vue` 拨通这一部总机（全站单例）。
- 业务页只做两件事：订频道听消息，或请总机帮喊一句（`invoke`）。
- 频道号长这样：`类型_编号`，例如告警弹窗是 `21_1`。没在花名册登记的频道，总机收得到也**不会转给你**。

## 2. 什么时候会碰到

- 传输中心进度条在动
- 导出 Excel / 图片包要等「做好了」才开始下
- 右上角弹出新告警
- 飞行监控画面上的 OSD、时间轴在刷新

## 3. 一条链路看懂

1. 你登录了 → `useSystemSocket` 发现有 Token → 拨总机
2. 总机连上 `/lidar-notify-hub`，工牌要**去掉** `Bearer `（和 HTTP 相反）
3. 后台喊四种喊法：喊所有人 / 喊某角色 / 喊某用户 / 喊用户列表
4. 总机拆信封（里面可能还套信封），读出 Type、Code
5. 拼成 `21_1` 这种频道号，只转给订了这个频道的页面
6. 你退出登录，总机挂断

```text
登录 → 拨通总机 → 后台推消息 → 拆信封 → 按 Type_Code 分给订了频道的页面
```

## 4. 业务页怎么写

听广播：

```437:443:src/views/system/transmission-center/useTransmissionCenter.tsx
  useSocketSubscribe<Record<string, unknown> | undefined>(
    SOCKET_TOPIC.TRANSMISSION_CENTER_IMPORT_UPDATE,
    handleTransmissionCenterExportUpdate
  )
```

组件卸载会自动退订，不用自己记着取消。

飞行监控还要请总机帮登记「我看这架飞机」：

```296:303:src/views/flight-dashboard/real-time-monitor/modules/realTimeMonitorSocket.ts
export async function subscribeRealTimeMonitorHub(
  subscription: RealTimeMonitorSubscription
): Promise<void> {
  await invokeSignalRHubMethodWhenReady(
    'SubscribeRealTimeMonitor',
    subscription.stationCode,
    subscription.patrolDeviceCode
```

**不要这样**：在页面 `new WebSocket(...)` 或再 `new HubConnectionBuilder`。会变成第二部总机，现有频道全部听不到。

| 想改什么 | 打开哪个文件 |
|----------|----------------|
| 新增加一种推送 | `src/utils/socket/topics.ts` + 页面 `useSocketSubscribe` |
| 登录后何时连/断 | `src/hooks/core/useSystemSocket.ts` |
| 总机地址 | `src/utils/socket/index.ts` 里默认 `/lidar-notify-hub` |

常用频道（先混个眼熟，不必背全）：`19_*` 传输中心，`20_*` 飞行监控，`21_1` 告警弹窗。

## 5. 只要记住这几个点

### 一部总机，不是每人一根线

**类比**：前台只有一部电话。各部门分机听广播，不能每人再拉一条外线。

**代码里**：`WebSocketClient.getInstance` 单例；`App.vue` 调一次 `useSystemSocket()`。页面再用 `useSocketSubscribe` 往内存花名册上登记。

**合上书记住**：连接是全局的，订阅是页面的。

**别这样**：在某个列表页 `onUnmounted` 里销毁全局连接，其它页的进度条会一起死。

### 频道必须先上花名册

**类比**：总机只转「已登记分机号」。后台新开了 `22_1`，前台没登记，你耳朵贴在听筒上也是静音。

**代码里**：`SOCKET_TOPIC` 是白名单；解包后拼 `Type_Code`，不在表里就丢掉。

```1:11:src/utils/socket/topics.ts
export const SOCKET_TOPIC = {
  TRANSMISSION_CENTER_EXPORT_UPDATE: '19_1',
  TRANSMISSION_CENTER_IMPORT_UPDATE: '19_2',
  TRANSMISSION_CENTER_PROGRESS_UPDATE: '19_3',
  REAL_TIME_MONITOR_OSD: '20_1',
  // ...
  ALARM_POPUP_CREATED: '21_1'
} as const
```

**合上书记住**：新推送 = 先改 `topics.ts`，再订频道。

**别这样**：只写 `useSocketSubscribe`，不改花名册。

### 信封可能套信封

**类比**：文件袋里还有文件袋。前台会拆到露出 Type/Code 为止（最多拆 6 层）。

**代码里**：`unwrapBusinessContent` 看 `Data`/`data`。你在 handler 里拿到的，多半已经是里层对象。传输中心、导出模块有的又自己拆一遍，属于重复劳动，读的时候别被绕晕。

**合上书记住**：回调里不要再 `$payload.data.data` 往下钻，先打印看已经平铺没有。

**别这样**：按接口文档的「三层嵌套」在前端再拆三层。

### 想主动喊总机，要等接通

**类比**：电话还在拨号，你不能先喊「给我接监控室」。最多等大约 5 秒。

**代码里**：`invokeSignalRHubMethodWhenReady` 每 250ms 看一次通没通，最多 20 次。

**合上书记住**：`invoke` 不是立刻发出，没登录会空等然后报错。

**别这样**：未登录页调用 Hub 方法还以为是频道订错了。

## 6. 别踩这些坑

- 连上会弹「服务器连接成功」，刷新/重连也会弹。`src/utils/socket/index.ts`
- 名叫 `send` 的方法其实没发，只 warn。要用 `invoke`
- 总机 SDK 自己会重连，代码里又写了一套重连，两套并存
- 缺 Type 时，看到 `osd`/`item` 会猜成监控 `20_*`，别的包碰巧带 `item` 可能串台

## 7. 合上书自测

1. 业务页应该自己建连接，还是只订频道？
2. 后台新推了 `type=22 code=1`，前端只加了 subscribe，为什么收不到？
3. HTTP 的 Token 带着 Bearer，总机用的时候要不要带？

# 路由与动态菜单

> 读完只需要能答文末 3 问。细节用的时候再翻。

## 1. 先记住这句

> 大楼先只开放大门；刷卡进门后，前台按你工牌上的楼层清单，再给你配电梯权限。

- **大门** = 静态路由：登录页、403/404/500、个人中心。没登录也能到登录页。
- **楼层清单** = 后端返回的菜单。当前是 **backend 模式**：清单在「菜单管理」里配，不在 `src/router/modules` 里配。
- 配完清单，前台还要按清单**现场做电梯卡**（`addRoute`）。做完必须再刷一次卡，否则电梯还是按旧名单走。

## 2. 什么时候会碰到

- 登录后跳进系统、刷新页面
- 新页面做了，菜单里看不见 / 点进去是「组件未找到」
- 没权限的地址变成整页空白或退不出系统
- 改了 `system.ts` 却发现生产菜单没变

## 3. 一条链路看懂

1. 网站启动：电梯里只有大门那几层（`staticRoutes`）
2. 没登录乱逛 → 送到登录页，并记住你原来要去哪（`redirect`）
3. 已登录、楼层卡还没做 → 拉 `user-auth-info`，取出 `menus`
4. 把扁平菜单拼成树，登记到 Vue Router，侧栏也用这棵树
5. 你要去的楼层不在清单里 → 送回首页，或送到「带侧栏的无权限页」（还能点退出）
6. **登记完再 `next` 一次原地址**：因为这一趟导航开始时，新楼层还不存在

```text
大门（静态） → 刷卡（登录） → 按工牌做楼层卡（动态路由） → 再刷一次 → 进页面
```

## 4. 业务页怎么写

线上要能打开一个页，三件事缺一不可：

1. `src/views/.../index.vue` 文件真实存在
2. 菜单管理里的 **path** 和 **componentPath** 能对上这个文件
3. 该用户的角色被授了这个菜单

`src/router/modules/system.ts` 现在主要是对照/前端模式用。`appConfig.routeMode` 默认 `'backend'`，改这份文件**不会**自动出现在生产侧栏。

**不要这样**：只在 `system.ts` 加一个 children，就以为菜单出来了。

| 想改什么 | 打开哪个文件 |
|----------|----------------|
| 登录白名单、404 | `src/router/routes/staticRoutes.ts`、`guards/beforeEach.ts` |
| 菜单字段怎么变成 path | `src/router/core/MenuProcessor.ts` |
| 填的视图路径找不到组件 | `src/router/core/ComponentLoader.ts` |
| 一个菜单都没有时别整站 500 | `src/router/core/noMenuFallback.ts` |

## 5. 只要记住这几个点

### 先登记，再进门

**类比**：前台现场制卡需要几秒。你已经站在电梯口说「去 8 楼」，但 8 楼这层刚写进系统，必须重新刷一次。

**代码里**：`addRoute` 之后 `next({ path, query, hash, replace: true })`。直接 `next()` 会空白或 404。

**合上书记住**：动态路由 = 注册完再导航一次。

**别这样**：在 `login()` 末尾以为路由已经注册好了。登录只存 Token，真正做卡的是随后的守卫。

### 菜单在后台，不在 modules 文件

**类比**：墙上的楼层牌是物业打印的，不是你在装修图纸上画了就算数。

**代码里**：`routeMode === 'frontend'` 才用 `asyncRoutes`；否则 `MenuProcessor.getMenuList(data.menus)`。前端表上的 `meta.roles` 在 backend 模式**不会**在这里过滤（那函数写了但没人调用）。

**合上书记住**：生产菜单 = 菜单管理 + 角色授权。

**别这样**：只改 `src/router/modules` 去上线新菜单。

### 视图地址要像门牌一样精确

**类比**：物业写「8 楼 801」，电梯去找 `views/8楼/801`。写成「八楼住宅 801 室.vue」就找不到门，只会挂一块「组件未找到」。

**代码里**：会尝试 `../../views${componentPath}.vue` 和 `.../index.vue`。含中文的 component 会被丢掉。

**合上书记住**：`componentPath` 对 `/system/user`，文件在 `src/views/system/user/index.vue`。

**别这样**：填 `src/views/system/user/index.vue` 或带中文路径。

### 没楼层和没权限不是一回事

**类比**：工牌上一个楼层都没有，仍要能走到前台办退出，不能把人锁进故障电梯。走错了没权限的楼，也要留着侧栏。

**代码里**：空菜单注册 Layout 内 403；已登录却撞上全屏 404，会改送到带布局的无权限页。

**合上书记住**：空权限 ≠ 系统 500。

**别这样**：把「没菜单」当成初始化失败死循环重试。

## 6. 别踩这些坑

- 守卫和菜单转换有不少 `console.log`，会打出整棵菜单。`beforeEach.ts`、`MenuProcessor.ts`
- 快速连点时可能 `next(false)`，表现为点了没跳
- 菜单管理保存时会 `new` 一份路由注册器，和守卫那份不是同一个对象，兜底无权限路由可能漏挂（见《角色用户与菜单管理》）
- 默认首页写死 `/system/user`，没这个菜单时才改用第一项

## 7. 合上书自测

1. 现在改 `src/router/modules/system.ts`，生产侧栏会变吗？为什么？
2. 动态路由 `addRoute` 之后为什么不能直接 `next()`？
3. 打开一个新页，除了写 Vue 文件还要在哪里配置？

# 文件上传与下载

> 读完只需要能答文末 3 问。细节用的时候再翻。

## 1. 先记住这句

> 取件有三种柜台，别用错窗口：当场给文件、填单等短信、自己拿链接去下。

- **当场给**：接口直接把文件扔给你（`responseType: 'blob'`）。模板下载、头像上传走这种小窗口。
- **填单等短信**：先在传输中心开一张单，后台慢慢做。做好了总机喊你，再拿链接去下。导出 Excel、大模型上传走这里。
- **自己拿链接**：手里已经有 URL，交给 `downloadUrl` 去点浏览器的「另存为」。

三种窗口互不替代。导出接口成功，只表示「单子收下了」，不是「U 盘已经到你桌上」。

## 2. 什么时候会碰到

- 场景模型上传很大的文件
- 执行记录 / 告警导出 Excel、打包图片
- 传输中心列表里点下载
- 测点台账「下载导入模板」

## 3. 一条链路看懂

**大文件上传（场景模型）**

1. 选文件 → 先开一张传输中心单子，拿到 id
2. 点保存 → 用 FormData 把文件装进袋子寄出（袋上写 `File`、`Id`）
3. 进度如果要看，去订总机的 `19_*` 频道

**导出 / 列表下载**

1. 点导出或下载 → HTTP 只受理任务
2. 总机先说「做好了可以来取」（状态 13）→ 再调一次 download 接口
3. 总机再说「取件码来了」（状态 4，带 URL）→ `downloadUrl`
4. 离开页面会丢掉排队中的单，晚到的短信就作废

```text
小文件：接口 → 直接 blob → 浏览器保存
大文件：开单 → 上传 FormData
导出  ：开单 → 等 13 → 再取 → 等 4（URL）→ downloadUrl
```

# 角色用户与菜单管理

> 读完只需要能答文末 3 问。细节用的时候再翻。运行时怎么拦页面、藏按钮，见《权限控制》《路由与动态菜单》。

## 1. 先记住这句

> 先造房间（菜单/按钮/接口），再做钥匙串（角色），最后把钥匙串给人（用户）。人身上不直接挂房间钥匙。

配置侧的故事就这一条生产线：

1. **菜单管理**：造房间，写门牌（path）和房间图纸地址（componentPath）

3. **角色管理**：做钥匙串，把房间+抽屉+保险柜勾进去
4. **用户管理**：给人一把钥匙串（页面上是**单选一个角色**）
5. 这个人**重新登录**后，门禁和抽屉才按新串生效

- 用非超管账号去改别人的权限，保存后对方菜单变少了

## 3. 一条链路看懂

1. 点「菜单权限」
2. 树上出现的，是**你自己**现在有的菜单/按钮/接口（你没有的房间，树上都没有）

4. 绑了这个角色的人，下次领权限清单才变

**改菜单**

1. 增删改菜单
2. 当前这个浏览器会重新拉清单、拆掉旧电梯卡、再做新卡
3. 别人已经打开的系统，不会自动更新


| 标准答案 | **不会变，重新登录也不变。** 当前是 backend 模式，侧栏来自后台「菜单管理」+ 角色授权，不是这份前端路由文件。重新登录只会重新拉取**后台菜单**，不会改去读 `system.ts`。 |

要侧栏出现新页：写 Vue → 菜单管理配 path/componentPath → 给角色授权 → 用户重新登录。

### 8. 动态路由 `addRoute` 之后为什么不能直接 `next()`？

| | |
|--|--|
| 你的答案 | 直接 `next()` 会空白或 404 |
| 判定 | **部分对**（说了结果，没说原因） |
| 标准答案 | 这一趟导航开始时，路由表已经匹配完了。`addRoute` 只影响**下一次**导航，所以要 `next({ path, query, hash, replace: true })` 再走一遍。直接 `next()` 仍按旧表匹配，表现为空白或 404。 |

### 9. 打开一个新页，除了写 Vue 文件还要在哪里配置？

| | |
|--|--|
| 你的答案 | 页面上的菜单管理进行配置 |
| 判定 | **部分对**（少了授权这一步） |
| 标准答案 | 两处都要：① 菜单管理配 **path + componentPath**；② 把该菜单授给角色。只配菜单不授权，侧栏对这个人仍没有。 |
